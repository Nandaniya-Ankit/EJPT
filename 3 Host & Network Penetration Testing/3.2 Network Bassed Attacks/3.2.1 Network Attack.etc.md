## SNMP (Simple Network Transfer Protocol)
-> PORT : 161 UDP -> for SNMP Quaries
-> PORT : 162 UDP -> for Traps (notifications)

-> protocol used to monitor and manage the networked devices like _routers , switches , printers , servers etc_
-> It  allows network administrator to query , _System INformation_ , _configure certian settings_ & receive alerts on a specific event.

-> SNMP -- operates on UDP -- has 3 components 
	-> _SNMP Manager_ : use for querying and interacting with SNMP Agents 
	-> _SNMP Agents_ : software running on networked devices that responds to queries & sends traps.
	-> *Management information Base (MIB)* : A hierarchical DB that defines the structure of the data available through SNMP 
		-> Each data has a OID (Unique Identifier Data)

##### Steps
1. Identify SNMP Enables Devices
2. Extract system Information 
3. Identify SNMP Communication strings -- `snmp-brute.nse`
4. Retrieve Network Configurations
5. Collect User and Group information
6. Identify Services and applications

-> `nmap` : to identify if SNMP is open or NOT
	-> `nmap -sU -p 161 IP`
	-> `nmap -sU -p 161 --script snmp-brute.nse IP` : 
		-> used to brute server community stings (password).
		-> */usr/share/nmap/nselib/data/snmpcommunintes.lst* : default WL to brute communities
	-> `nmap -sU -p --scritp snmp-* IP`
		-> It will give all the possible information 

-> now let's way we found some valid comminty strings then we can use tool like `snmpwalk` to gather more information

-> `snmpwalk` : `snmpwalk -v VERSION -c COMMUNITY IP`
-> It's output is not much readable , so use the _nmap --script snmp-*_ thing to get the properly organised information extraction.

-> then we can bruteforce smb password on whatever user we found on the system.
-> and we can then login as RDP , or SMB using psexec etc

## SMB Relay Attack
#post-exploitation 

-> `nmap --script=smb2-security-mode.nse -p445 10.0.0.0/24`
	-> to find if message signing is disabled on any IP ! if disabled then that machine is a good vector for _RELAY ATTACKS_

1. Interception : setup a MITM by 
	-> Using ARP Spoofing |
	-> DNS Poisoning |
	-> Rouge Server.

2. Capturing Authentication : 
	-> when a client try to connect to the server it sends the auth data like hashes , we try to capture them.

3. Relaying to the legitimate server 
	-> Instead of decryption of hashes , we can use them to send `relays` on another server  in order to authenticate server.
	-> allows attacker to impernosate the user

4. Gain Access :
	-> If the relay is successful , we can then able to gain access

#### Steps
##### 1. ARP Poisioning 
-> telling _Client_ that i am the _GETWAY_ server (router). 
-> `arpspoof -i eth1 -t 172.16.5.5 172.16.5.1`
-> telling _GETWAY SERVER_ that i am the _CLIENT_ machine
-> `arpspoof -i eth1 -t 172.16.5.1 172.16.5.5`

##### 2. DNS Spoofing
-> setuping a fake _DNS SERVER_ on my local attacker machine , and mapping my attacker IP with the machine domain where the SMB is setup already.
	
-> so that , when the client try to connect to SMB server while sending relays , it will send to the attacker machine instead of actual SMB server

1. -> creating a fake DNS / hosts file , where the SMB domain is mapped with attacker machine.
```
echo "172.16.5.101 *.sportsfoo.com" > dns.txt
```

2. -> `dnsspoof -i eth1 -f dns.txt`
	-> command to setup dns
