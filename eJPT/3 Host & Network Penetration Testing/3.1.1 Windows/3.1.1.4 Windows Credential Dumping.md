# 1 Windows Password Hashes
->> Things to keep in mind

1. Password hashes store in `SAM` Database file - (Security Accounts Manager)
2. Auth and verification is faciliteted by `LSA` (Local Security Authority)
3. Windows NT kernel , keeps the SAM file locked 
	-> so , attackers use in-memory techniques & tools to dump the hashes form LSASS process
	-> In modern window versions , SAM database is encrypted with a `syskey`
4. _Administrative/Elevated_ privileges are required in order to access and interact with the LSASS Process. #important  

##### Types of Hashes in Windows
###### LM (LanMan) :
-> In windows before _NT 4.0_ , Before Vista.
-> It take the pass , divide in two part of server characters each or less , depending the length of the password
-> then , UPPERCASE all the letter and perform DES algo to both parts.
-> It is very easy to crack because of lack of salting.
###### NTLM 
-> It is a collection of auth protocols that are utilized in windows to failiitaes auth b/w computers.
-> Password is encrypted in MD4  hashing algorithm , while original password is disposed of.
-> Benefits over LM
	-> don't split hashes into chunks
	-> case sensitive
	-> allow the use of Unicode and special characters in password.
